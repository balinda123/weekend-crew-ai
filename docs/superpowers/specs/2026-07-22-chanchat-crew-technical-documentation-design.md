# 馋猫局儿技术文档设计记录

## 已确认的范围

- MVP 面向北京及周边朋友的美食短途组局，支持 4–10 人。
- 首版包含地点收集、地图、AI 行程、AA、私密攻略与复刻。
- AI 从 v0.1 开始参与截图结构化和行程编排，但不能代替确定性路线与账本逻辑。
- 产品角色为白色田园猫搭档：芝士负责路线/下一站，奶糖负责账本/攻略状态。
- 地图服务默认使用高德；通过 `MapProvider` 隔离，未来可替换。

## 文档结构决策

采用三份文档而不是只拆成“前端一份、后端一份”：

1. `TECHNICAL-DESIGN.md` 是共同真相，定义架构、实体、数据流、安全边界、成本与 API 原则。
2. `FRONTEND-IMPLEMENTATION.md` 定义小程序页面、组件、状态与测试责任。
3. `BACKEND-IMPLEMENTATION.md` 定义 API、数据、提供商适配、AI 管道与测试责任。

这种结构避免前后端各自维护一份接口定义，导致字段、权限、异步状态不一致。

## 2026-08-14 后续需求增补

本文件保留 2026-07-22 的文档结构决策。当前产品基线已升级到 v0.3，权威内容以 PRD 和四份活跃文档为准，新增：

- 首页公开行程广场与独立搜索结果页。
- 地图抽屉内的地点合集和可编辑行程列表。
- 小红书/抖音公开分享链接的受控解析、截图 OCR 降级与批量地点确认。
- 旅行积分和 AI 次数双重成本护栏。
- 浅色个人中心与设置页面。
- 项目级 sync-requirements-docs Skill，用于需求变更后的跨文档同步与一致性检查。
- 2026-08-14 第二次增补：添加地点删除地图中心点选点，只保留 POI 搜索和公开分享链接识别。
- 我的信息架构调整为我创建的、我加入的、收藏；攻略创建后默认私密，发布审核通过后才进入公开广场。
- 新增微信 code 登录与头像/昵称显式确认方案；最新基线要求首次确认完成后才能进入产品。
- 首页与我的统一浅色卡片系统，并在原型中提供四套渐变配色候选。
- 2026-08-14 第三次增补：首次进入改为强制微信登录，身份交换后确认头像昵称，再进入首页或恢复分享目标。
- 新增公开攻略独立详情页；公开 DTO、发布快照和套用副本均硬性排除 AA 账单、分摊与转账关系。
- 添加地点面板改为双分段轻量布局，固定搜索与候选操作尺寸，作为 375px/390px 适配验收项。

- 2026-08-14 第四次增补：个人积分指标合并进资料卡；公开攻略改为地图加“地点总览/行程列表”只读抽屉。
- 行程节点新增 day_index 日期归属，AI 生成、手动新增、编辑、跨日拖拽和公开套用统一受攻略起止日期约束。
